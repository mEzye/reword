# Локальна диктовка та окремий сервер

Для розпізнавання Reword використовує transcribe.cpp 0.4.2 і Parakeet UK v3 Q8_0. Python, PyTorch та платні API не потрібні.

## На одному комп'ютері

Після збірки `Reword.exe`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-speech.ps1
```

Сценарій завантажує приблизно 740 МБ моделі в `models` і нативний рушій у `speech-runtime`, перевіряючи SHA-256. Завантаження можна продовжити повторним запуском сценарію. Модель за замовчуванням працює на CPU, використовує два потоки й завантажується один раз при старті.

Запусти Reword. Меню трея **Налаштування…** відкриває режим, обчислення, стан, останній результат і гарячі клавіші. Початкова комбінація — **Ctrl+Alt+H**; її можна змінити без перезапуску в розділі **Гарячі клавіші**. Під час утримання комбінації програма записує мікрофон, розпізнає короткі фрагменти й дописує підтверджені слова в активне поле. Після відпускання завершує останній фрагмент без повторного вставлення вже введеного тексту. Enter не натискається. На Windows, якщо активне вікно змінилося, вставлення для цього запису припиняється; повний результат залишається у полі останнього транскрипту в **Налаштуваннях**. Для введення в консоль адміністратора Reword має працювати з таким самим рівнем прав. Один запис обмежений десятьма хвилинами. Мікрофон відкривається лише на час затискання; у паузі запису немає. Хвилі реагують на рівень мікрофона.

## Розпізнавання під час запису

Parakeet UK v3 — модель для готових фрагментів, тому потокова поведінка реалізована в клієнті. Перший знімок звуку надсилається приблизно через секунду, наступні — кожні 800 мс. Поки рушій зайнятий, проміжні знімки замінюються найновішим; фінальні записи мають окрему обмежену чергу. Старі проміжні результати не накопичуються.

Слова дописуються після узгодження двох послідовних гіпотез. Пауза на 600 мс завершує фразу; вже завершені фрази повторно не розпізнаються. Для безперервного мовлення контекст обмежений приблизно вісьмома секундами з вибором тихішої межі наприкінці вікна. Це зменшує затримку на довгих записах, але межі фрагментів можуть впливати на точність.

Вставлення дописує лише новий підтверджений суфікс і не видаляє текст у сторонньому застосунку. Якщо модель згодом змінить уже введений префікс, автоматичне дописування для цього запису припиняється; уточнений повний текст доступний в останньому транскрипті в **Налаштуваннях**. Цей самий клієнтський механізм працює з локальним рушієм і окремим сервером; HTTP-протокол сервера не змінюється.

Локальний рушій працює в окремому дочірньому процесі через loopback. Важка компіляція C++ не додається до збірки Reword. UI не чекає моделі чи HTTP-запиту. Процес рушія завершується разом із батьківським процесом, включно з аварійним завершенням батьківського.

## CUDA

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-speech.ps1 -Backend cuda
```

Після цього вибери **NVIDIA CUDA** у розділі диктування вікна **Налаштування** й натисни **Застосувати**. **Автоматично** запускає GPU в окремому процесі та переходить на CPU при помилці запуску або падінні GPU-обчислень; той самий аудіозапис повторюється без втрати. CPU-режим не ініціалізує Vulkan чи CUDA. Наявність CUDA-ядер сама по собі не гарантує сумісності старої карти з готовою версією CUDA-рушія; фактичний обчислювальний backend показано у стані та журналі.

## Один сервер для кількох комп'ютерів

На комп'ютері з моделлю:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-speech-server.ps1 -Listen 0.0.0.0:8178 -Device cpu
```

Для CUDA заміни `-Device cpu` на `-Device cuda`; за потреби задай `-Threads 4`. Вікно показує журнал моделі; Ctrl+C зупиняє сервер. Він створює випадковий ключ у `speech-server.token`. На клієнтських комп'ютерах у розділі диктування **Налаштувань** вибери **Окремий сервер**, введи адресу на кшталт `http://192.168.1.10:8178` і цей ключ. Клієнтам не потрібні ні модель, ні CUDA. Доступ через брандмауер налаштовується на серверному комп'ютері; Reword не змінює правила самостійно.

Кілька комп'ютерів можуть надсилати записи: одна завантажена модель обробляє їх по черзі. Зовнішній сервер працює, доки не закрити його консоль; локальний дочірній сервер належить своєму клієнту. За межами довіреної локальної мережі використовуй HTTPS через reverse proxy або VPN.

## Конфіг і перевірка

Журнали програми та моделі зберігаються у `%LOCALAPPDATA%\Reword\logs\app.log` і `%LOCALAPPDATA%\Reword\logs\speech.log`. Кожен обмежений приблизно 1 МіБ.

`speech.ini` біля exe зберігає режим і адресу. Серверний ключ не потрапляє в Git, звук у файли не зберігається. Віддаленому серверу надсилається PCM16 WAV, 16 кГц, моно; обробка звуку виконується через WASAPI/CPAL і FFT-ресемплер Rubato.

Для перевірки без мікрофона передай готовий WAV такого формату:

```powershell
.\Reword.exe --transcribe-file=D:\audio\test.wav --output=D:\audio\result.json
```

Результат містить текст і час, включно з першим запуском моделі. `GET /health` і `POST /transcribe` приймають `Authorization: Bearer <ключ>`; POST містить сирий WAV у тілі й повертає JSON `text`, `backend`, `elapsed_seconds`. Це протокол Reword, а не OpenAI multipart API.

Windows є поточним середовищем перевірки. Код аудіо, HTTP і вводу тексту використовує бібліотеки для кількох ОС; для macOS/Linux потрібно окремо підготувати нативну бібліотеку, задати `REWORD_SPEECH_RUNTIME` та перевірити дозволи мікрофона/вводу. `REWORD_SPEECH_MODEL` дозволяє задати шлях до GGUF. Пакування й вставлення на цих ОС тут ще не перевірені.

Атрибуція моделі й рушія: [PARAKEET-NOTICE.md](assets/PARAKEET-NOTICE.md).

## Перевірка першої інтеграції

На поточному i3-6006U тестовий український WAV на 5,8 с розпізнано як «Проста перевірка розпізнавання мови». Перший повний локальний запит із запуском моделі зайняв близько 4 с. Перевірено два запити до спільного CPU-сервера, клієнтський режим окремого сервера, відмову без ключа (401), відмову для некоректного WAV (400), формат WAV і антиаліасинг ресемплера.

Готовий CUDA backend 0.4.2 не містить сумісних обчислювальних ядер для перевіреної GeForce 940MX (`sm_50`) і падає на обчисленні. Власна збірка через `build-cuda-sm50.ps1` розпізнала той самий WAV через CUDA0 за 2,99 і 2,09 с у двох послідовних запитах. Автоматичний перехід на CPU також перевірений з несумісним готовим рушієм. Це не вимірювання якості на великому корпусі й не гарантія затримки для інших записів.

Для 940MX готується окрема збірка `ggml-cuda.dll` із transcribe.cpp 0.4.2, CUDA 12.8 і `CMAKE_CUDA_ARCHITECTURES=50`. Сценарій `build-cuda-sm50.ps1` використовує портативні інструменти в `D:\Tools`, показує прогрес і пише `target\cuda-sm50\build.log`. Він не замінює робочий DLL автоматично: новий backend потрібно спочатку перевірити розпізнаванням на карті. Наявність зібраного DLL сама по собі ще не підтверджує сумісність.
